# ページの翻訳

更新日：2026-11-22

ページ側（`page/`）の段落の集め方、書き込み、訳す順番と送信、書き換えの監視、上部のバー、元に戻す処理。

## 操作

| 操作 | 動き |
| --- | --- |
| ボタンのメニュー「このページを訳す（Alt+T）」・`Alt+T`・範囲を選ばずに右クリック「このページを日本語に訳す」 | ページ全体を訳す。訳した後の `Alt+T` は原文⇄訳文 |
| 上部のバーの「訳文／原文／対訳」 | 表示を切り替える |
| 上部のバーの × ・ボタンのメニュー「翻訳をやめて元のページに戻す」 | 訳文を消して元のページに戻す。同じサイトの自動翻訳も止める |
| ボタンのメニューのモデルの切り替え | 訳したページを新しいモデルで訳し直す（届くまで前の訳を見せる） |

## 段落の集め方

`page/collect.js` の `collect`。

1. 文字のノードを TreeWalker でたどり、親から、段落の区切りにならない要素（`display: inline`・`contents`）をさかのぼる。ブロック要素と inline-block（ボタンなど）のほか、一覧の項目も独立した段落にする。
   - `li` は横並びでも項目の境界にする。項目そのものを残すので、サイトのCSSが疑似要素で描く区切りや、入れ子のリストの括弧が翻訳後も残る。短い項目は送信時にリストごとにまとめ、周りの項目の文脈をモデルへ渡す。
   - `dt`・`dd` も横並びで項目の境界にする。用語と説明は段落を分けてDOMに書き戻し、送信時は定義の組にする。表のセルは通常の `table-cell` で境界になり、パンくずに使うインラインのリンク自体は文中のリンクと同じ書式として扱う。
2. 段落ごとに、段落の中の要素をマーカーにして1行にする（下の「マーカー」、`page/paragraph.js` の `markup`）。要素の間の空白だけのノードは空白1つとして残す。残さないと、MDN のプロパティ名とバッジ（`<code>features</code> <span>Read only</span>`）が「featuresRead only」と1語になり、モデルが識別子と見て英語のまま返した（2026-11-11）。
3. 訳す価値が無い段落は除く（`shared/text.js` の `worthTranslating`）。
4. 集めた文字のノードを覚え（`state.seen`）、2回集めない。ノード→段落の対応（`state.owner`）は、文字が書き換わったときに使う。
5. 最も近いリスト・ナビ・ツリーの枝・表の行などを、まとめるための鍵として段落の `group` に持たせる。定義リストは `dt` と続く `dd` の組の鍵も持つ。送信する直前にも取り直し、DOMの移動に追従する。`h1`〜`h6`・`role=heading` とその子の段落は本文として扱う。

### 訳さないもの

| 対象 | 理由 |
| --- | --- |
| 日本語（かなを含む）の段落 | 訳す必要が無い |
| 文字（`\p{L}`）を含まない段落、英字1文字 | 記号・数字・`x` など |
| `script`・`style`・`pre`・`code`（段落の中のインラインコードは除く）・入力欄・`iframe` など | コード・入力 |
| 編集できる要素、`translate="no"`、`.notranslate` | ページの指定に従う |
| SVG・MathML の中（HTML 以外の名前空間） | グラフの文字や、グラフ部品が入れる `<style>` |
| `{ } ;` の多い文（80字超で2％超） | CSS・JavaScript のような文 |
| 拡張機能自身の要素（訳文・吹き出し・バー） | — |

SVG の中を名前で判定すると、SVG の中の要素は `tagName` が小文字（`style`）になるので、大文字の名前の表を通り抜けていた。2026-11-09、GitHub の利用状況のページで、グラフ部品（Highcharts）が SVG の中に置いた CSS（3373字）を段落として訳しに行き、モデルが CSS を写す生成を41秒続けて、その間ほかの段落が約50秒待たされた（作者の調査用のログで分かった）。名前空間で丸ごと除き、名前は大文字にそろえて比べ、CSS のような文も除くようにした。

### マーカー

段落（ブロックの中の一続きの文字。`<br>` でも分けない）を1つの単位としてモデルに渡す。流れ・守る条件・層の分担は [設計方針](11_設計方針.md)「段落のデータの流れ」。段落の中の要素は `page/paragraph.js` の `roleOf` だけで分類し、`shared/markup.js` の `encode` がマーカー付きの1行にする。番号は段落の中で出てきた順。

| 役割 | 段落の中の要素 | マーカー | 訳文での戻し方 |
| --- | --- | --- | --- |
| wrap | 段落の文字を含み、リンクか、親と見た目が違う要素（太字・斜体・色や背景・枠のあるバッジなど） | `<a1>…</a1>`（入れ子にできる） | 元の要素を `cloneNode(false)` し、訳した文字を入れる |
| code | インラインコード、`translate="no"` など訳さない要素。訳す文字を含まない要素（中がコードだけのリンクなど）も中身ごとこれにする | `<c1>…</c1>`（中身は文脈としてモデルに見せる） | 元の要素をそのまま写す |
| void | 文字の無い、見える要素（`<br>`・アイコン・画像） | `<v1/>` | 元の要素をそのまま写す |
| pass | 親と見た目が同じ要素（React などが細かく包む `span`） | 付けない | 中身だけを渡す |
| foreign | 入れ子のブロック・inline-block（ボタンなど）、ほかの段落の文字を含む要素 | 付けない | 触れない（別の段落として訳す） |

- 見た目の比較は計算済みのスタイル（太さ・斜体・書体・大きさ・色・背景・下線など・縦位置・大文字化・枠・余白）で行う。背景が透明なら親と同じとみなす。
- 要素と中のコードを別々のマーカー（`<a1><c2>X</c2></a1>`）にすると、モデルが毎回両方を写し、出力が増えた（2026-11-16、MDN の Navigator のページで出力トークン +21%）。訳す文字を含まない要素は中身ごと1つの `<c1>` にする。
- バッジ（MDN の「Read only」「Secure context」のような、角の丸い小さな枠の表示）は、枠の見た目を保つため要素のマーカーで囲む。バッジが並ぶだけの行（「<a1><c2>Navigator.bluetooth</c2></a1> <a3>Read only</a3>」）は、まとめ訳しでモデルが英語のまま返しやすい。各バッジが短い英字（3語以下かつ24字以下）なら英語のまま受け入れ、訳し直さない（`shared/text.js` の `untranslated`、`shared/markup.js` の `labelsOf`）。日本語の文書でも Read only のままのほうが読みやすいため（作者の判断、2026-11-16）。訳し直すと、MDN の Navigator のページでリクエストが 68→114 回に増えた。1行で送られた行など、モデルが日本語に訳して返した場合はその訳を使う。
- 文の途中の `<br>`（語か読点の後で、小文字から続く）は手で折り返しただけの改行として空白にし、文をつなぐ。マーカーにすると、語順の変わる訳文で「…してください<br>。」のように文末へ移った（2026-11-16、0.8B）。
- 段落の文字がすべて1つの要素の中（見出しのリンク、太字だけの行など）なら、その要素を `root` とし、マーカーを付けずに訳文をその中に置く。コードの中は `root` にしない（コードの中身を地の文として訳してしまう。2026-11-16、MDN のサイドバーの「ブロックのリンクの中のコードだけ」の項目114件を訳しに行き、全体が81%遅くなった）。
- コードの中身は訳す価値の判定に入れない（コードだけの段落は訳さない）。
- PLaMo は段落単位のタグを保ったまま訳す。2026-11-09、リンク2つの文などで 0.8B・2B とも崩れなかった。2026-11-16、0.8B で、太字の見出しと `<br>` が並ぶ GitHub の Issue の段落、番号付きの空要素、入れ子のマーカー、生の HTML（属性つき）を試し、いずれも保った。マーカー8組の文では1組の閉じが落ちた（`decode` が要素を外して文字を残す）。
- 生の HTML は渡さない。訳文の改行がまとめ訳しの「1行＝1段落」を壊す、長い URL などの属性がトークンを使い書き換えられうる、モデルの出力を HTML として解釈することになる、ため。元の要素を写せば属性は確実に保てる。

**以前の作りと変えた理由（2026-11-16）**：以前はリンクとインラインコードだけを名指しでマーカーにし、原文は文字のノードだけを隠していた。名簿に無い要素は訳文から消え（Markdown の太字、`<br>` の改行。GitHub の Issue でログの行がつながった）、文字以外の中身は訳文表示で残った（インラインコードの空の箱を `data-plamo-shell` の推測で隠す対処、`<br>` が訳文の上に空行として並ぶ件）。症状ごとに直すと、要素の種類が増えるたびに例外が増えるため、段落の中の要素を1つの規則でマーカーにし、隠すのも段落の中身ごとにした（作者の指摘）。

## 書き込み

`page/write.js`。

- 訳文が届いた段落は、原文の文字のノードを `<span data-plamo-orig="done">` で包み（送るときに包んでいればそれに印を付け）、`root` の直下で最後の文字の後ろに `<span class="plamo-tr" lang="ja">` を置く。届くまでは原文をそのまま見せる。
- 訳文を要素に戻す（`render`）。`shared/markup.js` の `decode` が訳文を木にし（崩れたマーカーは捨てて文字を残し、閉じなかった要素は外す）、`render` は木を DOM にするだけ。コピーからは `id`・拡張機能の印・原文のラッパーを外す。訳文の文字は文字のノードとして入れ、HTML として解釈しない。
- 段落の中の要素で、中身がすべてその段落のもの（`page/paragraph.js` の `readParagraph` が返す `hide`）には `data-plamo-hide` を付け、訳文表示で丸ごと隠す。訳文に写しが入るので、太字・コード・`<br>`・アイコンが原文側に残らない。ほかの段落の文字や入れ子のブロックを含む要素は隠さず、その中の要素ごとに判断する。元のページに戻すときは印も外す。
- 表示の切り替えは html 要素のクラス（`plamo-mode-trans`・`orig`・`both`）と `page/page.css` だけで行う。切り替えは一瞬。
- 元に戻すときは、`.plamo-tr` を消し、ラッパーを外し、クラスを外す（`removeAll`）。

## 訳す順番と送信

`page/queue.js`。

- **キャッシュを先に置き換える**：ページのキャッシュ→Service Workerのキャッシュ（`cache-lookup`）の順に引き、ある段落はすぐ書き込む。残りだけを訳を待つ列（`state.pending`）に入れる。
- **訳す順番**（`page/priority.js`）：送るたびに、待っている段落すべての点数を測り直し、小さい順に送る。スクロールやマウスの位置で順番が変わる。点数は次の和。
  - 位置：画面内（上から）→下にある段落→上にある段落（下の2倍後回し）→見えない段落（閉じたメニューなど。`checkVisibility()` で見る。2026-11-06、韓国語版Wikipediaで閉じたメインメニューを本文より先に訳していた）。訳し直しでは原文を隠しているので、訳文の位置で決める。
  - 場所（画面の高さに対する割合）：注目している場所（ダイアログ・ツールチップ）−1、本文（`main`・`article`・`[role=main]`・`.markdown-body` など）0、どこでもない 0.25、ナビ（`nav`・`aside`・メニュー・本文の外の `header`・`footer`）1。本文の中にあるナビもナビとして扱う。ナビは、見えていても1画面分下の本文と同じくらい後になる。`h1` は、本文の外の `header` の中にあっても本文として扱う（ページのタイトルなので。`nav` の中の `h1` はロゴとしてナビのまま。sakutto の `dom/priority.ts` と同じ判断）。
  - 画面内の本文の段（`page/priority.js` の `markReading`、`shared/text.js` の `READING_TIER`）：見出し→第1段落→本文→注記の順に並べ、同じ段の中は上から。4段が画面1つ分に収まるので、画面内の段落はどれも画面外より先になる。パラグラフライティングの文章は、見出しと第1段落を読めば何の話かが分かるので、訳している途中でも先にそれを見せる（2026-11-12、作者の依頼）。
    - 見出し：`h1`〜`h6`・`role=heading`、または見た目で、太字（600以上）か本文より1.2倍以上大きい字の、80字以内で文末記号のない塊（GitHub のモデル名は太字の `p`）。ボタン・タブ・全部がリンクの段落は除く。
    - 第1段落：DOM 順で見出しの直後の最初の本文。間にあるボタンの文字・注記・ナビは飛ばす。
    - 注記：`role=note`・`small`・`figcaption`・`sup`・`sub`、斜体、本文の0.9倍未満の字。
    - 読み上げ用に1px へ縮めた文字（`sr-only`）は見えない段落として扱う。見出しの段に入れると、画面に出ない「Organization navigation」などを最初に訳していた。
  - 見出しを先に出しきる：画面内の見出し・第1段落を含むバッチを訳している間は、後ろの段だけのバッチを足さない（`queue.js` の `frontBusy`）。同時に送ると長い本文・注記と計算を分け合い、見出しが遅れるため。GitHub の Copilot の Models のページ（検証環境B、同時8本、交互3回）で、画面内の見出しと第1段落は約4.2秒で出そろう（0.8.4 はモデル名のバッチが約13秒）。代わりに、後ろに回した長い注記（約790字×3）が遅れて始まるので、画面内の訳し終わりは 16.9→20.0秒、全体は同じ（33.5秒）。
  - 段落の性質：全部がリンクの段落（メニューの項目・パンくず）+0.3、12字未満の短いラベル +0.15（見出しには足さない）。`nav` などで囲まれていないメニュー（GitHub の設定の左側など）も、これで後回しになる。
  - まだ訳されていない段落にマウスを約0.3秒載せたら、列の先頭に回す（通りすがりでは入れ替わらない）。読みたい所にマウスを置けば、そこが次に送られる。
- **訳している途中の表示**：送ったバッチの段落だけ、原文を少し薄く（不透明度 0.55）し、動かさない。送る時点で原文の文字を `<span data-plamo-orig>` で包み、ラッパーに `data-plamo-working` を付ける。訳を待つだけの段落には付けない。訳文が届いたら印を外し、訳文を0.25秒でふわっと出す。進み具合は上部のバーの線と待ち時間で見せる。
  - 段落ごとに動かさない理由：訳している間は、ページの描画と翻訳の計算が同じ GPU を使い、送った段落は1ページで百数十件になる。以前の光の帯（`background-clip: text` の背景を毎フレーム動かす）は、光っている段落すべてを毎フレーム描き直し、翻訳の GPU の順番を奪っていた。検証環境A（RTX 4060）の MDN のページ（191段落）で、光の帯をやめると全体 24.3→6.5秒（-73%）、最初の行 1.46→0.64秒。描き直しの要らない不透明度の明滅に変えても、止めて薄くするだけより全体 +6%・最初の行 +78%（0.58→1.04秒）遅かった（いずれも交互3回の中央値、`docs/10`「実際のページの描画と翻訳の取り合い」）。
- 原文のラッパーは、訳文が届く前は `data-plamo-orig="`（見せたまま）、届いたら `data-plamo-orig="done"`（訳文表示で隠す）。
- **訳し終わった行から出す**：まとめて送った段落は、生成の途中で行が終わるたびに（0.25秒おきまで）先に書き込む（Offscreen Documentの `partial` → Service Worker → ページの `show-partial`）。最後の返事で、行がずれた・訳されていない行は訳し直した訳に置き換わり、キャッシュには最後の返事だけを入れる。
- **短い項目のグループ**：周りの項目を文脈として渡すため、マーカーを除いて40字以下で文末記号のない項目をDOMのグループごとに集める（`collect.js` の `groupOf`、`shared/text.js` の純関数 `groupedChunk`）。鍵は最も内側の `ul/ol/menu/nav/details/tr`、またはARIAの `list/menu/menubar/navigation/tree/tablist/row`。ツリー内の `role=group` は枝の境界にする。表は行を選び、入れ子のリストは内側を選ぶ。`dl` は下記の定義の組として別に扱う。
  - 各リクエストの先頭は従来の点数順で選び、同じグループの残りを集める。小さい同種グループは分断せずに相乗りさせ、8行に達したところで終える。グループの完結に必要なら最大12行まで許す。ナビ・フッターのリストは同じ種類の項目として扱う。
  - 上限は400字・入力256トークン見込み。英数字は4字で1、記号・非ASCII文字は1字で1とし、各行に2トークンの余裕を足す概算で、PCには依存しない。12行またはこの予算を超えるグループは8行を目安に分割し、最後の片も他グループとは混ぜない。送信済み・キャッシュの項目もグループの大きさの判定に使う。
  - 本文は本文同士で従来の8行・400字まで詰め、短い項目とは分ける。途中に別の種類があっても同種同士で詰め、小さいリクエストの乱立を防ぐ。見出し要素（`h1`〜`h6`・`role=heading`）、構造が明示されない段落、説明を開く `details` の要約1つは本文として扱う。目次ナビの見出しも本文に含める。
  - 交互計測では `queue.js` の `GROUP_CHUNKING` だけを `false` にすると、優先順だけの8行・400字へ戻る。既定は `true`。
- **定義リストの組**：`dl` の `dt` と続く `dd` は、用語と説明の文脈を保つため同じページリクエストに入れる。連続する複数の `dt` と、それに続く複数の `dd` を1組とし、`div` で包まれた組や `dd` 内の段落・リストにも対応する。送信する前にDOM順を数値へ変換し、純関数がリクエスト内を `dt`→`dd` の順に並べる。リクエストを選ぶ優先度は、その中で最も優先度の高い段落の点数で決まる。
  - 説明は字数や文末による短い項目の判定から外し、組の境界で分割する。目安は短い項目と同じ8行・最大12行・400字・入力256トークン見込み。1組だけで予算を超えるときは、組を保って単独で送る。長い `dd` も同じページリクエストに含める。小さい定義の組を相乗りさせるときも、本文の定義とナビ・フッターのリンク集は別のリクエストにする。
  - 1200字を超える `dd` を含む組も同じリクエストに入るが、翻訳コアはそのリクエストの各行を個別に訳す（長い段落の扱いは `core/translator.js` の S3）。
- **同じ文は1回だけ送る**：バッチを作るとき、同じ文の段落（表の部署名・役職名のように何十行も同じもの）は1段落だけ送り、残りは「同じ文の訳を待つ」側（`waiting`、鍵は世代と文）に回す。送信中のバッチと同じ文も同じく待たせる。訳し終わった行の途中表示と最後の返事で、待っていた段落にも同じ訳を書き込む（待っている間も光らせる）。取り消し・失敗のときは列に戻し、訳し直し・翻訳の終了の前の世代の待ちは捨てる。以前は最初の訳がキャッシュに入るまで同じ文を何本も同時に送っていた（2026-11-10、韓国の研究機関の職員検索で「배터리3센터」が行ごとに並ぶページ。30行×3列の試験ページで、91段落を5回・最大40行の送信で訳し終えた）。
- **同時に8本（設定で変えられる。2026-11-10に4本から変更）**：Offscreen Documentは同時実行数＋1のスロットで読み込み、残り1本を選択範囲・テキスト翻訳に空けておく。同時実行数はPCごとの設定（`docs/03`「PCに合わせる調整」）。1本返るたびに次を送る。同時に送るとモデルがまとめて計算し、全体が速くなる。
- **最初の1バッチだけ先に送る**：訳す流れの始め（訳し始め・スクロールで新しい段落が出たとき。訳すものが無くなった後の最初の送信）は、いちばん優先のバッチだけを送り、その最初の行が届く（`show-partial`）か、返事が来てから残りを送る。時間では区切らない。0.4秒の保険で区切っていた間は、原文の読み込みが遅いPC（検証環境Bの内蔵GPUで約0.6秒）で保険が先に切れ、残りの読み込み 2.2秒が最初の行を止めていた（`docs/10`「最初の行（N9）」）。全部を同時に送ると、最初のバッチの原文の読み込みがほかの同時実行数分と一緒に計算され、最初の行が遅れるため（検証環境Bの同時8本で最初の1バッチ 3.3秒、4本で 2.1秒。`docs/09`「同時実行数の上限」）。sakutto の「最初に待たれる文を満員の組と一緒に読ませない」と同じ考え方で、`docs/10` の N9。検証環境Bの実際のページで、最初の行は約3.3→約1.0秒、全体は約+4%（ぶれと重なる）。流れの途中で送信中が0本になったとき（見出しを訳し終えた直後など）は先送りしない。先送りすると、1行の長い段落が訳し終わるまで最初の行が届かず、残りが約5秒止まっていた（2026-11-12）。
- **失敗**：返事が失敗なら、そのバッチを列に戻して止め（`state.halted`）、バーに赤で出す。利用者が表示を切り替えたらもう一度試す。
- **世代**：訳し直し・翻訳の終了のたびに `state.generation` を増やし、古い返事を捨てる。
- **計測**：訳し始めに画面内の段落を覚え、「画面内」「全体」の秒数をバーとコンソールに出す。

## 書き換えの監視

`page/main.js` の `observe`。

- MutationObserver を html 要素に付ける（GitHub などはページを移るときに body ごと入れ替えるため）。body の中に足された要素だけを集める（head の script・style は訳さない）。
- 書き換えが0.7秒落ち着いてから、足された要素を集め、文字が変わった段落をマーカー付きで作り直して訳す。ドラッグで凡例が次々に変わる間などに、途中の文を訳しに行かない。
- 同じ段落の訳し直しは3回まで（訳すたびにページが書き換える React などの描き直しで止まらなくならないように）。
- 消えた段落のリクエストは、落ち着くのを待たずに取り消す（`cancelStale`）。
- 集め済みの文字のノードがページへ戻ってきたら、その段落を出し直す（`revive`）。描き直し（React などの hydration）が同じノードを原文のラッパーの外へ入れ直して訳文を外した段落は、訳文を書き直す。訳を待つ間にページから一度外れて待ち列から落ちた段落は、列へ入れ直す。同じ段落の出し直しは3回まで。

## 上部のバー

`page/bar.js`。閉じた Shadow DOM の中に作り、html 直下に置く（ページの CSS の影響を受けず、段落の収集にも入らない）。要素の要素は `page.css` の `.plamo-ui`（枠・影）を当てないよう、別のクラス（`.plamo-ui-host`）にする（当てると左端に小さな点が出た）。

バーの下の縁に、進み具合の細い線（訳し終えた段落 ÷ 訳し終えた＋待っている＋送っている段落）を出す。訳している間だけ見える。

表示する内容（上から優先）：モデルの準備などの知らせ → 止まっている → 「訳しています… 残り N 段落（送信中 n本・最長 s秒・t tok/s）」 → 「訳し終えました：N段落、画面内 a秒・全体 b秒・t tok/s」。待っている秒数は1秒おきに出し直す。段落だけ訳したときは「ページ全体を訳す」も出す。

トークン/秒は、返事が届いたバッチの生成トークン数（Service Workerの `translateBatch` が `stats.tokens` に足す。キャッシュから返した分は0）を、送ったバッチが1本以上あった時間の合計からモデルの読み込みの待ち（`stats.loadMs`、同時に送ったバッチは同じ読み込みを待つので最長を1回だけ）を引いた時間で割る（`page/state.js` の `tokensPerSecond`）。読み込みを引かないと、最初のページでは保存済みのモデルでも読み込みの約8秒が入り、検証環境Bの試験ページで12トークン/秒と低く出た。同時に送った同時実行数分をまとめた全体の速さで、1本あたりではない。スクロールを待つ間など、何も送っていない時間は入れない。トークン数は返事が届いたときに足すので、訳している途中は送信中の分だけ少なめに出る。返事がまだ無いときは出さない。
