# 開発と検証

更新日：2026-11-16

## 読み込み方

1. `brave://extensions` を開き、右上の「開発者モード」をオンにする。
2. 「パッケージ化されていない拡張機能を読み込む」で `<repository>\extension` を選ぶ。
3. ツールバーのパズルのアイコンから「PLaMo翻訳（ローカル）」をピン留めする。

コードを変えたら、`brave://extensions` で拡張機能の再読み込み（↻）を押し、開いているタブも読み込み直す（`page/watch.js` はページを読み込むときに入るため）。権限が増えたときは確認を求められる。

拡張機能の JS はビルドせず、フォルダーをそのまま読み込む。同梱 wllama の JS・WASM は固定入力から自前ビルドする構成へ移行中。ビルドと採用候補の比較は [wllama のビルドと計測](08_wllamaビルドと計測.md)、採否の根拠は [性能の仮説検証](09_性能の仮説検証.md) を使う。

### 常設の単体試験が守るもの

常設の単体試験は、壊れても普段の利用では気づけないまま何かを失うものだけに置く（このリポジトリの `AGENTS.md`）。見ればすぐ分かる崩れ（訳されない、遅い、順番が違う）は通しの試験と実際の使用で確かめ、単体試験を足さない。性能パッチの採否の関門は `node --test tools/profile/comparison.test.mjs` で確かめる。

| 守る部品 | 壊れたときに黙って失うもの |
| --- | --- |
| 長い段落の分割（`shared/text.js` の `splitLong`） | 長い段落の一部の文が訳文から抜ける。片が長すぎると生成の上限で訳文の後ろが切れる |
| 止まらない生成の検出（`shared/text.js` の `runaway`） | 正常な訳文や、原文にある繰り返しを含む訳文が、途中で打ち切られる |
| まとめ訳しの行と段落の対応（`core/translator.js` の `translateBatch`） | モデルが1段落を複数行に分けて返したとき、訳が隣の段落へずれ、後ろの段落の訳や1段落の2行目以降が抜ける。訳は付いて見えるので気づけない |
| 段落のマーカーの文法（`shared/markup.js` の `encode`・`decode`） | 訳文から太字・リンク・コード・改行が消える、崩れたマーカーで文の残りが太字・リンクになる、訳文を HTML として扱う |
| 設計の決まり（`tools/architecture.test.mjs`） | 層の依存、純粋なモジュール、マーカーの文法の正本、分類と書き込みの分担が崩れ、症状ごとの例外が積み重なる（[設計方針](11_設計方針.md)） |
| 性能パッチの採否の関門（`tools/lib/perf-trace.mjs`） | 訳文を変える・打ち切る・リンクのマーカーを落とすパッチを採用し、同梱の wllama で訳が黙って変わる |

Node 24 で動かしている。Brave の場所は既定で `C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe`（環境変数 `BRAVE` で変えられる）。

### 通しの試験の場面

`tools/e2e.mjs`。試験ページは、GitHub と同じように厳しい CSP（`default-src 'none'; script-src 'nonce-…'`）を付けて返す。ページ側のモジュールの読み込みが CSP の下でも動くかを確かめるため。

| 場面 | 合格の条件 |
| --- | --- |
| 新しく入れたときの設定 | 設定の版が4で、動作モードが sync に無い（PCごとの local に置く） |
| モデルの取得と読み込み | 返事が来る（初回は約30〜45秒） |
| ページ全体を訳す | 5段落に訳文が付く |
| 段落の中のリンク | 2つのリンクが元の href のまま訳文に残る |
| インラインコード | `<code>npm install</code>` が訳文に残り、文は訳されている。訳文表示で原文側のコードは幅0（空の箱が残らない）、訳文の中のコードは見える |
| 段落の中の要素 | GitHub のコメントの形（太字の見出しと行を `<br>` で並べた `<p>`）を1段落のまま訳し、訳文に `<br>` と太字が残る。訳文表示で原文側の `<br>`・太字・画像・コードが見えず、段落の上に隙間が無く、高さが原文の1.2倍以下。太字の中のリンク・画像・コード・中がコードだけのリンクが訳文に写り、見た目が親と同じ `span` と文の途中の `<br>` はマーカーにならない。対訳で原文と訳文のどちらも改行する |
| SVG・日本語を訳さない | SVG の中（長い CSS と文字）、後から足した SVG、日本語の段落に訳文が付かない |
| 同じサイトの別のページ | 対訳のまま自動で訳す |
| 描き直しで外された訳文 | 段落の中身を元の文字のノードだけに入れ直す（hydration の真似）と、5秒以内に訳文が戻り、原文の文字がラッパーの外に残らない |
| 元のページに戻す | 訳文・ラッパー・クラス・バーが消え、自動翻訳の記録も消える |
| 選択した段落を訳す | 選択にかかる2段落だけに訳文が付く |
| 訳す順番 | ヘッダー・サイドバー・本文・フッターがすべて画面に入るページで、本文のバッチをナビより先に送る（調査用のログの送信の順で見る。4バッチは同時に送られ生成も並んで進むので、届いた順では見られない） |
| 訳している途中の光 | 送った段落の原文のラッパーに印（`data-plamo-working`）が付き、訳し終えると外れる |
| 訳し終わった行から出す | 本文の訳文が、バッチの返事を待たずにばらばらの時刻に届く |
| キャッシュの件数と大きさ | 設定画面に出す件数・大きさが0より大きい |
| 「訳」アイコン | 英文を選ぶと出て、押すと吹き出しに訳が出る。日本語を選んでも出ない |
| テキスト翻訳 | 言語の混ざった2行が、どちらも日本語になる |
| キャッシュ | モデルを解放し、Service Workerも止めた後に、同じ文が1秒以内に返る |
| 今の設定で測る | 速さの測定が時間とトークン/秒を返す |
| CPU | CPU・4スレッドで訳せる |
| 未使用時の解放 | 最後に使った時刻を昔にすると、見回りでOffscreen Documentが閉じる |
| 調査用のログ | 記録が残る |

### 試験の作りの注意

- **毎回新しいプロファイル**（`tools/lib/browser.mjs` の `launch`）。一時プロファイルを使い回すと前回のService Workerが残って新しいコードが動かず、`chrome.runtime.reload()` で読み込み直すと、`--load-extension` で入れた拡張機能が戻らなかった（2026-11-09）。そのため毎回モデルを取得する。
- **拡張機能に tabs の権限が無い**ので、タブの番号は URL で探せない。タブを前面にして、前面のタブを拡張機能から引く（`tabIdOf`）。
- **右クリックのメニューは押せない**ので、Service Workerの `sendToPage` と同じ手順（`page/loader.js` を差し込み、指示を送る）を拡張機能の設定画面から行う（`toPage`）。
- **MHTML を返すとき**は、保存した部品以外の通信を止めるが、`chrome-extension://`（ページ側のモジュールの読み込み）は通す。止めるとページ側が動かない（2026-11-09、リファクタリング後に一度これで止まった）。
- **Service Workerを止める**ときは CDP の `ServiceWorker.stopAllWorkers` を使う。

## 速さの測定

### モデルとパッチの比較

モデル内部の高速化は `tools/profile.mjs` で、ページの収集・描画の影響を分けて測る。PowerShell で リポジトリ直下 へ移動し、[ビルドと計測](08_wllamaビルドと計測.md) の手順に従う。

1. 固定した入力と順序付きのパッチ一覧から、通常版と内訳用の版を作る。成果物の manifest・hash を残し、比較対象の版を確定する。
2. 同じモデル・同時実行数・ubatch で基準→候補→基準の順に測る。新しいプロファイル、読み込みとウォームアップを除いた測定、`cache_prompt: false` をそろえる。モデルの取得・照合には WORK の共有キャッシュを使う。
3. 通常版の全体・最初のバッチの時間、訳・マーカーを照合する。CPU 側の内訳は profile、GPU カーネル別の内訳は profile-gpu を使う。profile-gpu の同期・timestamp 読み戻しを含むホスト時間は、通常版の速さの採否へ使わない。
4. 観測・仮説・数値予測・変更・実測・判定を `docs/09` へ記録し、採用分を拡張へ反映する。`tools/e2e.mjs` は変更の区切りの最後に1回行う。

結果は WORK の `profiles/<時刻>/report.json` と `summary.md`、各回の raw イベントに残る。引数・出力の詳細、`tools/bench-loop.mjs` で候補を重ねる方法は `docs/08` を参照する。性能の数値は `docs/09` を出典として設計書へ反映する。

計測用の拡張コピーは、offscreen の翻訳要求の既定も引き継ぐ。旧設定との対照では `--reference-completion-extra` で `backend_sampling: false`・`backend_sampling_token_only: false`・`samplers: null` を明示する。固定版の server schema は null を項目の省略として扱うので、sampler は元の既定 chain に戻る。追加項目は `prompt` の直前へ挿入されるため、本体の sampling 指定はその前に置いて上書きできるようにしている。

`distribution` は現在の計測台本では同梱 vendor を npm 配布物の固定 hash と照合する。vendor を自前成果物へ差し替えた後に配布物を対照として測るには、元の配布物を別の成果物として供給する計測側の対応が必要。差し替え前の対照と差し替え後の通常版を混同しないよう、比較対象を確認してから測る。

## 調査用のログ

遅い・止まる・訳がおかしいときに、何がどこで時間を使ったかを確かめる。

1. 設定画面のいちばん下の「調査用のログ」をオンにする。
2. 同じ操作をする。待たされている間は、上部のバーの「送信中 n本・最長 s秒」を見ておく。
3. 設定画面の「ログを保存」で `plamo-translate-log-<時刻>.json` をダウンロードフォルダーに保存する。

ログはService Workerのメモリーに直近3000件。Service Workerが止まると消えるので、操作の後すぐに保存する。ページの文は先頭60字だけ残す。

| 出所 | 出来事 | 主な項目 |
| --- | --- | --- |
| ページ | 送信 / 受信 / 取り消し / 取り消し済み / 書き換え / キャッシュ | `id`（バッチの番号）、`lines`・`chars`・`texts`、`ms`（返事までの時間）、`inflight`・`pending` |
| Service Worker | 完了 / 取り消し済み / キャッシュ | `requestId`（`page:<タブ>:<枠>:<id>`）、`ms`、`requests`（モデルへのリクエスト回数）、`fallback`（行がずれて1行ずつ訳した） |
| model | 生成 / 取り消し | `loadMs`（モデルの読み込み待ち）、`firstMs`（最初の1字まで。ほかのリクエストの順番待ちを含む）、`genMs`（生成）、`chars`・`tokens`、`cut`（打ち切った） |

読み方の例（2026-11-09、GitHub の利用状況のページ）：受信の `ms` が飛び抜けて長い `id` を探し、その送信の `texts` と、同じ `requestId` の model の `genMs`・`chars` を見る。`:root { --highcharts-color-0 …` を送って `genMs` 41178・`chars` 3195 になっていたので、CSS を段落として訳していたと分かった。
