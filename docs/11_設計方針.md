# 設計方針

更新日：2026-11-16

症状ごとの例外を積み重ねず、データの流れを読める形に保つための決まり。変更の前に読み、変更が決まりに合うかを `npm test`（`tools/architecture.test.mjs`）で確かめる。決まりを変えるときは、この文書と検査を同じ変更で直す。

## 原則

| 原則 | このリポジトリでの形 |
| --- | --- |
| 単一責任 | 1つのモジュールは1つの役割を持つ。段落なら、範囲を決める（`page/collect.js`）、中身を読む（`page/paragraph.js`）、文法（`shared/markup.js`）、書き込む（`page/write.js`）を分ける |
| DRY（正本は1つ） | 規則・文法・判定は1か所に置き、写しを作らない。目印の文法は `shared/markup.js`、要素の判定（行の中の要素・訳さない要素）は `page/dom.js`、段落の中の要素の分類は `page/paragraph.js` の `roleOf`。ツールも正本を読み込む |
| 開放閉鎖 | 新しい種類の要素は、分類規則（`roleOf`）の結果として扱いが決まる。流れの途中に要素名やサイトを名指しした分岐を足さない |
| 依存の向き | 下の「層」の表の向きだけに依存する。純粋な層（`shared/markup.js`・`shared/text.js`・`shared/prompt.js`）は DOM・chrome に触れず、ページ側・裏方がそれに依存する |
| インターフェース分離 | 使う側は持ち主のモジュールから直接読み込む。まとめて再輸出する中継のモジュールを作らない |
| 契約の型 | 層の間は決めた形のデータ（段落のトークン列、訳文の木）で受け渡す。受け取る側は相手の内部（DOM の形、正規表現）を見ない |

## 層

| 層 | 役割 | 読み込んでよい層 |
| --- | --- | --- |
| `shared/` | 純粋な規則・文法・設定・通信の名前 | `shared/` |
| `core/` | 何をどうまとめて訳すか、モデル・控え | `core/`・`shared/` |
| `background/` | 裏方（メニュー・タブ・設定・ログ） | `background/`・`core/`・`shared/` |
| `offscreen/` | モデルの実行 | `offscreen/`・`shared/`・`vendor/` |
| `page/` | ページの段落・書き込み・バー | `page/`・`shared/` |
| `ui/` | 拡張機能の画面 | `ui/`・`shared/` |

## 段落のデータの流れ

```text
DOM ─collect─▶ 段落の範囲（ブロックと文字のノード）
    ─readParagraph（roleOf）─▶ トークン列・marks・hide・root
    ─encode─▶ 目印付きの1行 ─▶ 裏方・モデル ─▶ 訳文
    ─decode─▶ 訳文の木 ─render─▶ 訳文の DOM（root の中）
    ─apply─▶ hide の要素に印（訳文表示で隠す）
```

守る条件：

1. 訳す単位は段落（ブロックの中の一続きの文字）。要素の種類によって段落を分けたり、別の経路を作ったりしない。
2. 段落の中の要素は、`roleOf` の役割（wrap・pass・code・void・foreign・none）のどれかにだけなる。役割の決め方は見た目と意味の一般的な性質（行の中か、文字を含むか、親と見た目が違うか、リンクか、訳さない指定か）で決める。
3. 訳文表示で原文側に残るのは、ほかの段落のもの（foreign）だけ。この段落の中身は `hide` で丸ごと隠し、訳文には写しを入れる。
4. モデルの出力は `decode` を通して木にし、文字は文字のノードとして入れる。HTML として解釈しない。
5. 目印の文法は `shared/markup.js` にだけ書く。
6. モデルの癖への対処（改行が文末へ移るなど）は `encode` の規則として置き、計測の日付と数字を添える。構造（見た目）を落として速さを得る規則は、作者の判断なしに入れない（2026-11-16、バッジの見た目を落とす規則を作者の判断で外した）。

## 不具合を直す手順

1. 流れのどの段で、どの条件が破れているかを特定する。症状の出た要素やサイトではなく、段と条件で言う。
2. その段の規則を直す。「この要素だけ」「このサイトだけ」の分岐で症状を消さない。避けられないときは、なぜ一般の規則で扱えないかを判断の記録に残す。
3. 純粋な段（`encode`・`decode` など）なら単体試験、見た目なら通し試験のページに題材を足す。
4. ページ側の変更は、実際のページの再生（`node tools/page-replay.mjs <MHTML> --extension <前の版> --compare extension`）で、前の版と速さ・訳の崩れを比べる。GitHub のように構造の多いページと、MDN のように段落・リンクの多いページの両方で見る。計測は変更を固めてから1回だけ、作者が PC を使っていない時間に行う（AGENTS.md）。

## 機械での確認

`npm test` が次を確かめる。

| 検査 | 止めるもの |
| --- | --- |
| 層の依存（`tools/architecture.test.mjs`） | 上の層の表に無い依存 |
| 純粋なモジュール（同） | `shared/markup.js`・`shared/text.js`・`shared/prompt.js` からの DOM・chrome の利用 |
| 目印の文法の正本（同） | `shared/markup.js` 以外での目印の書き方・正規表現 |
| 分類と書き込みの分担（同） | `page/write.js` での要素の種類の判定、`page/write.js` 以外での隠す印の付与 |
| 目印の文法（`tools/unit.test.mjs`） | 太字・リンク・コード・改行が訳文から消える、崩れた目印で文の残りが太字・リンクになる、訳文を HTML として扱う |
