# PDFの翻訳

ブラウザーの内蔵ビューアで開いたPDFを、拡張機能のPDF翻訳のページで開き直し、レイアウト・リンク・しおりを残したまま日本語にしたPDFを作る。見ているページから訳し、訳し終えた文を画面に重ねる。ページの段落がそろうと、重ねた表示を保存にも使う訳したPDFのページに差し替える。

## 目的と品質の基準

外国語のPDFを日本語で読めるようにする。Androidの画面翻訳と同じく、原文のレイアウトに忠実であることより、読めることを優先する（2026-11-16、作者の判断）。

| 優先 | 基準 | この版の扱い |
| --- | --- | --- |
| 1 | 訳漏れ・文字の重なりがなく、日本語で読める | 守る。原文を消せない文字は背景色で覆って上に訳文を書く |
| 2 | リンク・しおり・表・図を残す | 守る。リンクの範囲は訳文の位置へ移す |
| 3 | 原文と同じレイアウト | 許容する。訳文が枠に収まらなければ文字を縮める（最小0.7倍） |

[要件](01_要件.md)の優先順位（外へ出さない＞誤訳しない＞レイアウトを崩さない）は変えない。PDFの中身・訳文は外へ送らない。

## 入口

| 操作 | 内蔵ビューアでPDFを開いているとき |
| --- | --- |
| Alt+T・ツールバーのメニュー「このPDFを訳す」 | PDF翻訳のページ（`ui/pdf.html?src=<PDFのURL>`）を隣のタブで開く |
| 範囲を選ばずに右クリック | 「このPDFを日本語に訳す」で同じページを開く |
| 文章を選んで右クリック | 「選択範囲を日本語に訳す」（テキスト翻訳。0.9.3から変えない） |

内蔵ビューアで表示している文書かどうかは、`page/watch.js` が知らせる文書の種類（`document.contentType`）で判定する（`background/pages.js`）。`application/pdf` のときだけPDF翻訳のページを開き、ほかの種類（画像など）は従来どおりテキスト翻訳を開く。

`file://` のPDFは、利用者が拡張機能の詳細で「ファイルのURLへのアクセスを許可」をオンにしたときだけ、上と同じ操作で訳せる（`host_permissions`・`content_scripts` に `file:///*`。0.10.1、作者の承認）。PDF翻訳のページは `file://` を `fetch` で読めないので `XMLHttpRequest` で読む。オフのときは判定もタブのURLの取得もできないので、ツールバーのメニュー（ボタン・右クリック）の「PDFファイルを開いて訳す」でPDF翻訳のページを開き、ファイルを選ぶかドラッグして訳す。

## データの流れ

訳したPDFは1つだけ作り、ページを差し替えるときと保存するときに使う。0.14.0から、差し替えを待つ間は最初の文から読めるよう、途中の訳文を画面に重ねる。この間だけ画面と保存したPDFが一致しない。保存に含まれるのは、段落がそろいWorkerが書き終えたページの訳文。

```text
PDFのバイト列 ─pdf.js─▶ 画面（原文の文書）
  ─（Worker：pdf/worker.js）openPdf（PDFium）─▶ 訳したPDF（原文の写しから始める）─extractParagraphs─▶ 段落
  ─translate（画面経由で Service Worker。見ているページから、設定した同時実行数まで）
    ├─ 生成中の訳文 ─▶ 画面の途中表示
    └─ 確定した訳文 ─▶ 画面の途中表示にも渡し、差し替え後の描画まで残す
  ─（ページの段落がそろったら、そのページを1回だけ）writePageAt─▶ 訳したPDFのそのページを書き換える
  ─（初回はすぐ、その後は間隔を空ける）save─▶ 版（その時点の訳したPDF全体）─pdf.js─▶ 書いたページを版のページに差し替える（下の「表示」）
保存：訳したPDF ─finishPdf（pdf-lib・harfbuzz）─▶ 使っていない字形を抜き、しおりを訳したPDF
```

- PDFium の処理（段落の読み取り、ページの書き込み、保存）は PDF翻訳のページの Worker（`pdf/worker.js`）で行い、数百ページでも画面の操作を止めない。翻訳は Worker から頼めない（`chrome.*` が無い）ので、Worker が画面に頼み、画面が Service Worker へ送る。
- 訳したPDFの各ページは、そのページの段落の訳文が全部そろったときに1回だけ書く（原文のテキストのオブジェクトの道筋は書く前のページで数えたもので、同じページを2回書くと道筋がずれる）。日本語フォントは最初に1回だけ丸ごと埋め込み、全部のページで共有する（ページを書くたびに読み込むと、使われなくなったフォントも PDFium が保存し続け、ファイルが太る。2026-11-17 に確かめた）。
- 版は訳したPDF全体を保存したもの。PDFium の保存はページの番号付け（リンク・しおりの飛び先が指す番号）を変えないので、版のページを原文の文書のビューアにそのまま差し替えられる。PDFium の追記型の保存（`FPDF_INCREMENTAL`）は、変更が無くても全体を写し直して2倍の大きさになったので使わない。

### 訳す順番と同時実行（`pdf/queue.js`）

- ページが訳文に替わるまでの時間は、そのページの最後の段落がそろうまでの時間で決まる。そこで、表示中のページから送信し、続くページは距離順に選ぶ。表示中のページより前のページへの距離は、従来どおり1.5倍に数える。移動後は、空いた枠から新しい表示位置で選び直す。
- ページ内では、文字数が最も多いフォントサイズを本文の基準にし、見出しと第1段落を [Webページの翻訳](04_ページの翻訳.md#訳す順番と送信) と同じ `headingLike`・`markLeads` で判定して先に送る。同じ原文はPDF全体で1回だけ訳す。
- 本文は共通の `chunk` で8行・400字までにまとめる。上限を超える1段落は単独にする。空き枠が残るときは、同じページの本文のバッチを分けて並行で訳す。表のセルやラベルのような短い項目は、文脈を残せるようにまとめたまま送る。
- Webページと同じPCごとの同時実行設定を使い、最初の返事を待たずに残りを送る。フォントを待つ間も翻訳を進め、書けるようになったページはWorkerで順に1回だけ書く。中止・別のPDFを開くときは送信中のバッチをすべて取り消し、中止後の再開では確定していない分だけを送る。
- 段落を分ければ、1つのリクエスト内で前の段落が終わるのを待たずに済む。代わりにリクエストごとの入力処理が増え、同じGPUで複数の段落や後続ページを訳すため、計算の遅いGPUでは最初のページがかえって遅くなることがある。

### 生成中の訳文

- 途中表示でも段落はまとめて訳す。Offscreen DocumentがWebページの翻訳と同じ `previewLine` で文末までを取り出す。改行まで生成した行は、句点のない表の見出しやラベルも1行分を送る。バッチの各行をキャッシュ分も含む元の段落番号に戻し、依頼元のPDF翻訳の画面にバッチごとのPortで返す。
- バッチの行数が合わない場合や未翻訳の行を見つけた場合は、訳し直す段落の途中表示を取り下げる。行と段落の対応はバッチが終わるまで暫定なので、取り下げ前に別の段落の訳が見えることがある。生成ごとの番号で、訳し直す前の途中経過を捨てる。中止・文書の切り替えではバッチのPortを閉じ、確定済みの段落と差し替え済みのページは途中経過で上書きしない。
- 長い段落（`LONG_TEXT`）では、同時に訳す片のうち先頭の片だけを途中表示する。片の完了順にかかわらず文頭から読める。同じ原文が複数箇所にある場合（`byText`）は1回の翻訳を共有し、出現箇所ごとの色と書式で表示する。

### 段落の組み立て（`pdf/extract.js`）

1. PDFiumのテキストページから1文字ずつ、文字・原点・外接の四角・フォント名・太さ・色・属するテキストのオブジェクトを読む。文字の大きさは、フォントの大きさ（Tf）に文字の実際の変換（`FPDFText_GetMatrix`。テキストの行列・CTM・埋め込みのフォーム（Form XObject）の行列を掛けたもの）の縦の拡大率を掛けた値にする。Tf だけでは、縮めて描くPDF（Webページから作った予約確認で行列が0.6倍）の訳文が1.7倍ほど大きくなった（0.10.9、作者の報告）。
2. 同じ基線で間の空かない文字をセグメントにする。上付き文字（小さく、基線が近い文字）は同じセグメントに含める。目次の点線（`. . . .`）は別のセグメントに分ける。
3. 左端がそろい、行送りの間隔で続き、大きさと太さが同じセグメントを段落にする。同じ行に別のセグメントがある行（表のセル）からは次の段落へつなげない。箇条書きの印（`•` など）は訳さずに残す。
4. 文字の無い段落（番号・点線）と、3ページ以上で同じ位置に同じ文字列がある段落（ヘッダー・フッター）は訳さない。

### 書き込み（`pdf/write.js`）

- 訳す段落の文字を含むテキストのオブジェクトを消す。同じオブジェクトにある訳さない文字（目次の番号・点線、箇条書きの印）は、元のフォント・大きさ・変換行列で1文字ずつ置き直す。
- 訳文が原文と同じ段落（型番・住所・規格番号など）は、原文を残す。
- 埋め込みのフォームの中の文字は、PDFiumがフォームの中身を書き直さないため消せない。その段落は、原文の外接の四角を背景色（四角の中で文字の下に見えている色。下の「状態と描画の流れ」）で塗り、上に訳文を書く。見た目は日本語になるが、検索・コピーでは原文が残る。
- リンクは訳文の位置へ移す。原文では1つのリンクが行ごと・入れ子の複数の注釈になっていることがある（LaTeX の hyperref など。Kvaser の取説の「Section 3.6 … (page 10)」は2行・4つの注釈）。訳した段落の中の注釈を飛び先（URI、または飛び先のページと位置）ごとにまとめ、1つ目を訳文の位置へ移して残りは消す。訳文が複数行にまたがるときは、範囲（Rect）を行の外接にし、行ごとの範囲を QuadPoints に入れる（pdf.js は行ごとにリンクを置く）。0.11.0 までは文字から見つけた1つだけを外接の大きな四角へ移し、残りが原文の位置に残って、1つのリンクが大小3か所に見えた（作者の報告）。
- 訳文は段落の左端から、元の行の幅で折り返す。英数の並びは分けず、日本語は1文字ずつ折り返し、行頭禁則（、。など）はぶら下げ、行末禁則（（「など）は次の行へ送る。下の段落に重ならない行数に収まらなければ、文字と行送りを0.05倍ずつ0.7倍まで縮める。

### フォント（`pdf/fonts.js`・`pdf/subset.js`）

Noto Sans JP（標準・太字、SIL Open Font License）を初めて使うときに固定URL（jsDelivr の npm パッケージ `@expo-google-fonts/noto-sans-jp@0.4.4`）から取得し、大きさとSHA-256を確かめてから Cache Storage に保存する（約5.7MB×2）。拡張機能のZIPには入れない。Worker がフォントを用意したら、画面もキャッシュから同じフォントを読み込む。字幅はどちらも FontFace と OffscreenCanvas の `measureText` で測る。

訳したPDFには、フォントを丸ごと1回だけ埋め込む。保存するときに、訳文で使った文字の字形だけを残したフォントに差し替える（`pdf/finish.js`）。PDFium が書く日本語の文字は字形の番号そのもの（`Identity-H`、`CIDToGIDMap` なし）なので、harfbuzz の `hb-subset` で字形の番号を保ったまま（`RETAIN_GIDS`）抜く。番号を保つので見た目は画面と変わらない。埋め込んだフォントは、`FontFile2` の `Length1`（元のフォントの大きさ）で見分ける。533文字で1書体約350KB、4ミリ秒。

### しおり（`pdf/outline.js`）・保存の仕上げ（`pdf/finish.js`）

PDFiumにはしおりを書き換えるAPIが無いので、保存するときに訳したPDFを pdf-lib で開き、字形を抜くのと同じ処理の中で、しおりの見出しを本文の見出しの訳文で置き換える。本文に同じ見出しが無いものは原文のまま残す。見出しと段落の対応（`pdf/titles.js`）は、画面の見出しの欄と同じ。

pdf-lib の読み書きは既定で数十オブジェクトごとにタイマーで区切る。PDF翻訳のページが裏に回るとブラウザーがタイマーを間引き、20ページでも約51秒かかったので、区切らずに一度で処理する（`parseSpeed`・`objectsPerTick` を `Infinity`）。

暗号化されたPDF（パスワード無しで開けるが、編集などを制限したもの。メーカーの取扱説明書に多い）は pdf-lib が開けないので、フォントは丸ごとのまま（約6.8MB増える）、しおりは原文のまま保存する。本文はPDFiumが暗号化と制限を保ったまま書き換える（暗号化は外さない）。2026-11-16、HIOKIのPDFで作者が気づき、制限付きで暗号化した試験用のPDFで再現・確認した。

## 層

`pdf/` はPDFの読み取り・書き込み。`pdf/`・`shared/`・`vendor/` を読み込む。PDF翻訳のページ（`ui/pdf.js`）は `pdf/worker.js` を Worker として動かし、メッセージでやり取りする（種類は `pdf/worker.js` の冒頭）。画面は、見出しの対応（`pdf/titles.js`）、段落の配置（`pdf/plan.js`）、フォントの読み込み（`pdf/fonts.js`）を直接読み込む。翻訳はService Workerに頼む（`pdf/` は `chrome.*` に触れず、訳す関数を引数で受け取る）。決まりは[設計方針](11_設計方針.md)「層」。

## 表示：pdf.js のビューアとページの差し替え（0.11.0）

PDF翻訳のページは pdf.js（4.10.38、Apache-2.0）のビューアで原文を表示し、ページの段落がそろうたびに、そのページを訳したPDFのページに差し替える。拡大縮小・リンク・文字の選択・検索は pdf.js のものを、訳したPDFのページにそのまま使う。訳し終えた後も同じ画面で読み続ける。

### 内蔵ビューアを使わない理由

- 内蔵ビューアはブラウザーに組み込まれた拡張機能のページ（`chrome-extension://mhjfbmd…`）で、ほかの拡張機能はスクリプトを差し込めない（セキュリティの境界）。
- PDFの中身はPDFiumが描いた絵で、段落を差し替えられるDOMが無い。
- 埋め込んでも外から送れる指示は印刷などに限られ、表示中のページ・倍率・スクロール位置を読めない。
- 表示を変えるにはPDFを渡し直すしかなく、そのたびに読み込み直して拡大率・位置が戻り、ちらつく。

### 状態と描画の流れ

PDF翻訳の画面は、store が知らせる状態に合わせて描く。表示中のページを訳したPDFのページに差し替えるときは、新しいページを描き終えるまで確定した訳文を重ねておく。

```text
Worker の知らせ（pdf/worker.js）・ボタン ─store の関数─▶ 状態（ui/pdf-state.js）─知らせ─▶ ページの差し替え（ui/pdf-pages.js）・途中表示（ui/pdf-overlay.js）・見出しの欄・ボタン
差し替え後の描画完了（pdf.js の pagerendered）─ui/pdf-pages.js─▶ store ─知らせ─▶ 重ねた訳文を徐々に消す（ui/pdf-overlay.js）
```

- 状態（`ui/pdf-state.js`）：表示（訳文・原文）、原文の文書、訳したPDFの最新の版、書いたページ、段落の途中表示、見出しの訳。変えるのは store の関数だけで、変えたら対象を知らせる。
- ページの差し替え（`ui/pdf-pages.js`）：各ページに出すべき文書は、訳文の表示で書いたページなら最新の版、それ以外は原文。出している文書と違うページだけを `PDFPageView.setPdfPage` で差し替え、ほかのページは描き直さない。新しい版が届いたとき、描いてあって中身の変わらないページ（前の版で書いたページ）は前の版のまま出しておき、描いていないページだけを最新の版へ移す。出しているページが無くなった版は閉じるので、メモリーに残るのは原文、最新の版、描いてあるページが使っている版だけ。描いてあるページを差し替えると pdf.js は描き終わるまでページを空にするので、差し替える前の絵の写しを描き終わるまで重ねて、ちらつかないようにする。pdf.js の PDFPageView は文字の層とリンクを読み上げ用に結び付ける `TextAccessibilityManager` を使い回すので、差し替えるときに捨てて作り直させる（残すと、リンクの要素の ID が同じ新しいページで前のページの文字の番号を引き、文字の層の作成が止まった）。
- 途中表示（`ui/pdf-overlay.js`）：訳文が届くまでは原文に背景色を0.45で重ねる。届いたら四角を背景色で塗り、訳文に続けて薄い原文を描く。原文から取り除く文の数は訳文の文数と同じにするので、文を分ける訳やまとめる訳では切れ目がずれる。段落が確定したら Worker の `status: 'done'` に含まれる確定訳文を描く。pdf.js が拡大縮小などでページを描き直した場合は層の要素を置き直す。
- 差し替えの間は、差し替え前の絵の写しより手前に確定訳文を表示する。表示中の新しいページを描き終えたときに絵の写しを外し、CSS の `opacity` を0.25秒かけて下げて重ね表示を消す。画面外にある書き込み済みページでは描画を待たずに重ね表示を消す。原文と訳文の切り替え、訳し直し、中止、別のPDFを開くときの表示切り替えは即時に行う。
- 重ねる四角には、その段落の原文の背景色（`p.background`）と文字色（`p.color`）を使う。背景色は PDFium で描いた原文から段落ごとに1回求める（`pdf/background.js`）。四角の中で文字色に近い画素を除き、最も多い色を採る。四角の外の縁を使うと色の違う表で隣の行の色を拾う。訳したPDFでも、文字に同じ `p.color`、埋め込みフォームの原文を覆う四角に同じ `p.background` を使う。
- 途中表示とPDFへの書き込みは、同じ段落幅・基線・下端を使って `planParagraph` で訳文を折り返し、必要なら文字と行送りを縮める。背景を塗る四角は原文の文字の外接範囲から取り、訳文は計算した基線に描く。薄い原文は訳文の後ろに空きがある分だけ表示する。途中表示はフォントの取得中も代替フォントで描き、取得できたらPDFへの書き込みと同じ Noto Sans JP で配置し直す。

### 表示と操作

- pdf.js のビューアの中は標準の大きさの測り方（`box-sizing: content-box`）にする。拡張機能の共通の `*{box-sizing:border-box}` が効くと、ページの絵だけが枠線の分小さくなり、文字の層・リンクの層との位置が下へ行くほどずれた（0.11.2）。
- 文字の選択・コピー・リンクは、出しているページ（原文、または訳したPDF）の pdf.js の文字の層・リンクの層をそのまま使う。訳したPDFのページでは日本語を選べ、リンクは訳文の位置にある（保存したPDFと同じ）。
- 「原文」「訳文」は、書いたページに出す文書を原文と最新の版で切り替える（状態の表示を変え、ページの差し替えが合わせる）。
- 原文の文字の層は透明な文字で選択範囲だけを見せる。拡張機能の共通の `::selection` は文字に色を付けるので、PDF翻訳のページでは透明に戻す（付けたままだと、選んだところで原文が二重に見えた。2026-11-17、作者の報告）。
- 見出しの欄（`ui/pdf-outline.js`、0.10.6）：画面の左に PDF のしおりを折りたためるツリーで出し、「☰ 見出し」で開閉する（開閉はこの画面に覚える）。見出しははじめに全部開いておく（0.10.8、作者の希望。しおりの「開いて表示する」の指定には従わない）。訳し終えた段落と同じ見出しは訳文で出し、「原文」の表示では原文に戻す。見出しと段落の対応は保存する PDF のしおりと同じ（`pdf/titles.js` の `titleTranslations` を Worker が送る）。しおりの無い PDF では欄にその旨を出すだけにし、本文から見出しを推定しない（作者の判断、2026-11-17）。開閉の矢印の箱は見出しの1行目と同じ高さ（`--ol-line`・`--ol-pad`）から決め、1行目の真ん中に置く（0.10.7。共通のボタンの最小の高さ 36px が効いて下にずれていた）。
- 戻る・進む（0.10.6）：見出し・文書の中のリンクで移るとき、移る前の位置をブラウザーの履歴に積む（pdf.js の `PDFHistory`）。「← 戻る」「進む →」とブラウザーの戻る・進む（Alt+←・→）で行き来できる。履歴はこの PDF を開いてからの分だけで、最初の位置より前へは戻らない（PDF翻訳のページから出ない）。
- 幅・高さに合わせる表示は、見出しの欄の開閉やウィンドウの大きさの変更で合わせ直す（表示する欄の `ResizeObserver`）。
- 上の帯の操作は「移動（見出し・戻る・進む）」「翻訳（翻訳を開始・訳文・原文）」「表示（大きさ・並べ方）」「ファイル（訳したPDFを保存・PDFを開く）」のグループ（`.tools`）に分け、グループの間に縦の区切り線を引く。区切り線は各グループの左に持たせ、並べる枠（`.toolbar`）が左端を切り取るので、折り返した行の頭には線が出ない。中身が全部隠れているグループは出さない（`:has`）。「訳したPDFを保存」は塗りつぶす補助操作（`button.tonal`）にする（0.10.6、作者の希望）。
- 開いただけでは訳さず、「翻訳を開始」を押してから訳す（作者の希望）。表示の大きさは「幅に合わせる」「高さに合わせる」「100%」と拡大・縮小、ページの並べ方は「1ページ」「見開き（奇数が左）」「見開き（表紙を単独）」（pdf.js の `spreadMode`）から選び、この画面に覚える。
- 画面は見ているページ（`currentPageNumber`）を Worker に知らせる。翻訳を頼んだ段落は `onStatus(段落, 'working')`、訳文がそろった段落は `'done'`、訳文が原文と同じ段落は `null` で知らせる。ページの段落がそろうと、そのページを書いて版を送る（`onVersion`）。
- PDF の外へのリンク（Web ページ）は新しいタブで開く（`PDFLinkService` の `externalLinkTarget`）。同じタブで開くと、戻ったときに PDF を開くところからやり直しになった（作者の報告）。
- 「翻訳を中止」で、頼んでいる翻訳を取り消し（Service Worker の `cancel`）、Worker は書いたページまでで止める。訳し終えたページは訳文のまま残り、保存もできる。取り消した文は訳し残しへ戻し、「翻訳を再開」で続きから訳す。訳している途中に別の PDF を開くと、今の翻訳を止めて Worker を捨て、新しい PDF を開く（0.11.0 までは何もせずに無視していた）。
- 「訳したPDFを保存」はWorkerが書いたページを仕上げて保存する。途中表示の文字は画面のみにあり、選択・コピー・リンクは下のPDFのページに対して働く。

### 確かめたこと（2026-11-17、試験用のBrave）

- pdf.js の Worker（`pdf.worker.min.mjs`）と PDF翻訳の Worker（`pdf/worker.js`、PDFium・harfbuzz の WASM）は、拡張機能の CSP（`script-src 'self' 'wasm-unsafe-eval'`）と COEP（`require-corp`）の下で動いた。pdf.js には `isEvalSupported: false` を渡す。
- Kvaser の取説（20ページ、0.8B、キャッシュなし）で、訳している段落が半透明になり、1ページ目は約12秒（日本語フォントの初回の取得を含む）で訳したPDFのページに差し替わり、全体は約95秒だった。途中の高さに合わせる・見開き、全ページを通して見て戻る、拡大縮小、原文・訳文の切り替え、日本語のドラッグでの選択（英語が混ざらない）、訳したページの目次のリンクで移って戻る、を確かめた。保存したPDF（1.17MB → 1.46MB）は本文・しおりが日本語。
- 画面に描いているページの絵と、保存したPDFの同じページを同じ大きさで描いた絵を画素で比べると、違う画素は1.2〜2.9%で、原文同士を同じ方法で比べたとき（1.3〜3.4%、描く位置の端数による文字の縁の差）と同じ程度だった。画面と保存したPDFは同じ。
- 300ページ・18MB の PDF（ページごとに文の違う試験用のもの）を、すぐに訳文を返す偽の翻訳（1回200ミリ秒）で通した。段落の読み取り1.5秒、1ページ目の差し替えまで4.1秒、全体71秒（翻訳を待つ時間だけで約45秒）、画面の長い処理（50ミリ秒以上）0回、画面のメモリー24MB。途中で150ページ目へ移ると、そのページから訳して差し替わった。保存は2.6秒。
- 速さのために直したこと：段落の読み取りで、フォント・太さ・色・大きさをテキストのオブジェクトごとに1回だけ読む（300ページで4.0秒 → 2.0秒、結果は同じ）。訳文を受け取ったらすぐ次を頼み、モデルが訳している間にページを書いて版を作る。版は保存にかかった時間の4倍は空ける（直す前は全体330秒）。
- 試験用のブラウザーの窓がほかの窓の後ろに隠れると、pdf.js の描画（`requestAnimationFrame`）が止まり、ページが描き終わらずに試験が落ちることがあった（利用者が見ているページでは起きない）。試験の起動（`tools/lib/browser.mjs`）に、隠れた窓の描画とタイマーを止めない設定を足した。

## 既知の制約

製品の事実としての制約。対応の予定は書かない。

- 訳文が枠に収まらないときは文字と行送りを縮める（最小0.7倍）。後ろの段落を押し下げて組み直すことはしない。
- 目次の点線は引き直さないので、見出しと点線の間が空く・詰まることがある。
- 製品名・人名も訳す（「Kvaser」が「クワサー」に、ローマ字の人名が推測の漢字になることがある）。
- 原文は「原文」に切り替えて見る。訳文の上で原文を見せる機能、ページの中を検索する欄は無い。
- PDFのページが訳文に替わるのは、そのページの段落の訳文がそろったとき。
- しおりの無い PDF では、見出しの欄は空（本文から見出しを推定しない）。
- 暗号化された PDF は、保存のときにフォントの使っていない字形を抜けず（約6.8MB増える）、しおりは原文のまま。
- 段落は全部のページを読んでから訳し始めるので、数百ページの PDF では訳し始めるまで数秒待つ（300ページの試験用の PDF で約1.5秒）。
- 回転したページ・CropBox のずれたページ・Word や DTP ソフトで作った PDF・2段組での段落の推定と表示は確かめていない。
