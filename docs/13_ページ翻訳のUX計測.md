# ページ翻訳のUX計測

画面内を先に読めるようにし、畳まれた部分も開く前に訳す。訳す範囲は減らさず、訳し漏れや訳の崩れを増やさない。比較の対象を揃えるため、各拡張が独自に数える完了件数ではなく、翻訳前の同じDOMを分母にする。

## 指標と採否

時刻の原点は、ウォームアップを済ませ、ページ翻訳の指示を送る直前。時刻は、表示文の変化や確定した訳文の反映をDOMで観測した時点とする。

| 優先順 | 指標 | 測るもの |
| --- | --- | --- |
| 守る条件 | 網羅率と訳の品質 | 畳まれた部分を含む全件。網羅率100%を要求し、原文の残り・行ずれ・マーカーの崩れを基準より増やさない |
| 主 | 画面内の各段落で第1文を読めるまで | 最初の画面に見えていた各段落（`<p>`）について、第1文を読めた時刻のうち最も遅いもの（`initialParagraphReadMs`） |
| 主 | スクロール後の各段落で第1文を読めるまで | 初期画面の全件が確定した直後に1画面分スクロールする。その瞬間に見える各段落について同じ方法で測る（`scrolledParagraphReadMs`） |
| 副 | 段落の訳し終わり | 同じ段落の集合について、確定が最も遅い時刻。初期画面は `initialParagraphDoneMs`、スクロール後は `scrolledParagraphDoneMs` |
| 副 | 画面内の全項目の完了 | 見出しや一覧の項目を含む。初期画面は `initialViewportMs`、スクロール後は `scrollFollowMs` |
| 副 | 見出しと第1段落の完了 | 初期画面にある本文の見出しと、その直後の最初の段落が揃うまで |
| 副 | 表示中の部分とページ全体の完了 | 画面外を含む表示中の全件の確定と、開始時に非表示だった項目も含めた全件の確定 |
| 見張り | 画面内に訳文が出始めるまで | スクロール前に、画面内のどこかで最初の1文が読めるまで（`firstViewportSentenceMs`） |

`record.inventory[].displayChanges` に、初期の表示文（`source`）から変わった時刻、その時点の表示文と位置を残す。両拡張で同じ規則を使い、日本語の文字を含み、原文と同じ文を除いた、文末記号で終わる文の最初の時刻を使う。原文の続きが画面に残っていても、訳文の文だけを数える。文末記号のない段落は、表示を確認できた確定時刻を使う。スクロール時点で該当するすべての段落が読めれば待ち時間は0とし、ページ末尾では実際の移動量も残す。

まず `record.inventory` と `ux.counts` で網羅率を確認する。`ux.coverage` は、確定の判定が変わった時刻ごとの件数と観測終了時の値を残す。スクロール後の指標は、初期画面の全件が確定しない、移動がない、移動後に対象がない、または対象の全件で指標に達しない場合は未到達とする。結果の `null` は未到達を表す。指標ごとに到達回数、到達した試行の中央値・最小・最大、未到達時の網羅率を併記する。主指標の比較は双方が全回到達した場合に行い、試行のばらつきも見て判断する。

`quality.unchanged` は、反映を確認できた項目のうち、空白を正規化すると原文と同じ項目の件数と一覧を残す。固有名詞を正しく残したのか訳し漏れなのかは、人が原文と対訳を読んで判断する。`quality.mockingword` は行ずれによる再試行・打ち切りやマーカー残りなどを数える。sakutto ではこの内部ログ由来の値を測っていない。`tools/replay-compare.mjs` の chrF は差の大きい訳を探すための値で、訳の正しさの点数ではない。同じ原文が複数ある場合、chrF は最初の1件、網羅率はDOM上の各件を数える。文字列の変化を完了とした旧計測とは、網羅率・到達時刻を直接比較しない。

## 分母と反映の判定

- 原文DOMから、段落、見出し、リスト項目、表のセル、ボタンなどのブロックを列挙する。インライン要素の文字は含める。入れ子のブロックは親に重ねて数えず、その前後にある親直下の文字も別件にする。同じ文字列が別の場所にあれば別件。
- 空白を詰め、英字またはハングルが2文字以上続き、仮名を含まない項目を対象にする。コード・数式、フォーム入力欄や編集領域、`translate=no` の原文、画像の代替テキスト、疑似要素や iframe 内は分母に入れない。本文は `main` / `article` / `[role=main]` を優先し、なければ `body` とする。ナビゲーション・補足・フッターは③からのみ除く。
- 原文の文字の矩形とCSSの表示状態で、初期画面内・表示中の画面外・非表示を区分する。閉じた `details` は `summary` 以外を別集計し、CSSで隠れたメニューも非表示に含める。メニューを開く操作はしない。非表示も、同じDOMに訳文が入ったかで判定する。
- 対象項目では、英字かハングルを含む元のテキストノードすべての反映を確認する。両拡張が翻訳対象外とする明示的な `.notranslate` 内のノードは反映の要件から外すが、分母や原文からは除かない。完了には少なくとも1ノードの反映が必要。
- Mockingword の確定は `data-plamo-orig="done"` と文字の入った `.plamo-tr`、コンテンツスクリプトの `state.owner` と `state.cache` を照合する。確定時にDOMを書き直さない版では、次のフレームで再確認する。
- sakutto 1.9.0（置き換え表示）は、`data-sakutto-id` を付けて元のテキストノードに書き込み、`data-sakutto-pending="1"` を外した一連のDOM変更を確認する。原文と同じ文字列への書き込みも観測できる。ブロックのIDだけ、途中の書き込みだけ、保留の解除だけでは数えない。拡張が失敗した一部を原文で補って確定した場合、DOMからモデルの返事と原文への代替を区別できない。
- `record.inventory[].evidence` に反映を確認した元のノード数、属性が確認できた数、確認対象の合計、`.notranslate` のノード数、項目内の表示文字の有無を残す。拡張が複数項目をまとめて訳しても分母は変えない。確定反映は確認できても個々の項目と表示文を対応付けられない場合は `quality.unmapped` に残し、原文と同じかは判定しない。印や書き込みが取れない項目は完了に入れず、観測できなかった件数として報告する。
- 保存ページ、ビューポート、端末ピクセル比、文字コード、対象項目と初期区分を記録し、同一ページ・画面条件で分母の指紋が変わったら比較を中止する。この計測では開始時のDOMを固定するため、新規挿入の自動翻訳は網羅率に混ぜず、別の機能試験で確認する。

## 実行条件

| 保存ファイル名 | ページ |
| --- | --- |
| `github-typescript-9998.mhtml` | GitHub・TypeScript Issue #9998 |
| `mdn-gpuadapter.mhtml` | MDN・GPUAdapter |
| `w3c-proposal.mhtml` | W3C・The Original Proposal of the WWW |
| `wikipedia-ko.mhtml` | 韓国語版 Wikipedia・월드 와이드 웹。メインメニューを閉じて保存する |

保存は `node tools/page-replay.mjs --save <URL> <保存先>`。実ページ・出力・外部拡張・モデルは Git 管理外に置く。各ページの基本はメインモニターで最大化したブラウザーの実ビューポートとし、画面寸法・位置・ビューポートを記録する。GitHub は別に 1200×800 CSS px でも測る。

Windows の対話デスクトップで、`BROWSER` に Chrome for Testing または Brave を指定する。試験用ブラウザーの前面化と `Alt+A` を使うため、計測中はPCを操作せず、他の重い処理も止める。各回は新しいプロファイルを使い、WebGPU・固定の0.8Bモデルが読み込まれたことを確認し、訳文キャッシュを空にする。sakutto は未改変の1.9.0と照合済みの専用GGUFを使う。拡張ごとのエンジン・モデル配布物・生成枠数は同一ではないため、実際の条件を結果に残す。保存ページとモデルはローカルから供給し、sakutto の権限は追加しない。

計測条件は `default`（このチェックアウトのMockingword）と `sakutto`。`--baseline` に比較するMockingwordの拡張機能フォルダーを渡すと `baseline` も選べる。ページ・画面の組ごとに各条件を5回以上計測し、試行ごとに開始条件を一つずらす。既定のMockingwordは8枠。`--parallel` で変更した結果は別に集計する。

```powershell
node tools/page-replay.mjs --ux --fixtures $fixtures --out $inventoryOut --inventory
node tools/page-replay.mjs --ux --fixtures $fixtures --out $runOut --rounds 6 --variants baseline,default,sakutto --baseline $baseline --sakutto $sakutto --sakutto-model $sakuttoModel
node tools/replay-compare.mjs "$runOut/w3c-baseline-1.json" "$runOut/w3c-default-1.json" --out $pairsOut
```

`$fixtures` は保存した4ページのフォルダー、`$baseline` は比較元のMockingwordの `extension` フォルダー、`$sakutto` は未改変の拡張フォルダー、`$sakuttoModel` は固定GGUF。空の出力先フォルダーを指定する。短い通し試験は `--pages w3c --rounds 1 --variants default` で実行できる。`wallMs` は準備とウォームアップを含む通しの実行時間で、翻訳開始からの各指標とは別に記録する。

最大化した画面だけを比べる場合は `--max-only`、そのビューポートを検証する場合は `--max-viewport 3440x1311` を指定する。`--extra-parallel 16 --extra-parallel-pages github,w3c` は、指定したページに限って `default` の同時16本を比較条件に追加する。

## 原因を調べるときの記録

診断は Mockingword の一時コピーだけに計測点を入れる。`dispatch.requests` はリクエストごとの送信・受信時刻、行数・初期画面内の行数と、該当する生成の時間を残す。受信や生成を観測できなければ配列は空のままにする。`dispatch.occupancy` は枠取得・解放から出した同時生成本数の推移で、GPU利用率ではない。制限時間で止まった回では、終わっていない生成の枠は集計されない。`dispatch.replyToNextSend` は未送信の対象が残る受信から次の送信までの時間。次の送信がなければ `null`。`dispatch.selection` は対象の点数計算と選択1回の時間・対象数。DOM監視と診断の上乗せがあるので、絶対値は配布版の利用時間とみなさず、同じ計測条件の候補どうしで比較する。
