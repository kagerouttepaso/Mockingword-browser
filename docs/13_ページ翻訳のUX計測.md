# ページ翻訳のUX計測

画面内を先に読めるようにし、畳まれた部分も開く前に訳す。訳す範囲は減らさず、訳し漏れや訳の崩れを増やさない。比較の対象を揃えるため、各拡張が独自に数える完了件数ではなく、翻訳前の同じDOMを分母にする。

## 指標と採否

時刻の原点は、ウォームアップを済ませ、ページ翻訳の指示を送る直前。DOMに訳文が入った時刻をミリ秒で記録する。描画完了の時刻ではない。

| 優先順 | 指標 | 測るもの |
| --- | --- | --- |
| 守る条件 | 網羅率と訳の品質 | 畳まれた部分を含む全件。網羅率100%を要求し、原文の残り・行ずれ・マーカーの崩れを基準より増やさない |
| 主 | ① 画面内の完了 | 開始時の画面に見えていた全件に訳文が出るまで |
| 主 | ② スクロール後の追従 | ①の直後に1画面分スクロールし、その瞬間に見える全件に訳文が出るまで。すでに揃っていれば0。ページ末尾では実際の移動量も記録する |
| 副 | ③ 見出しと第1段落の完了 | 初期画面にある本文の見出しと、各見出しの後の最初の段落が揃うまで |
| 副 | ④ 畳まれていない部分の完了 | 開始時に表示されている全件に訳文が出るまで。画面外も含む |
| 副 | ⑤ 全体の完了 | 開始時に非表示だった項目も含めて全件に訳文が出るまで |
| 見張り | ⑥ 最初の段落 | いずれかの `<p>` に最初の訳文が出るまで。悪化させない |

まず `record.inventory` と `ux.counts` で網羅率を確認する。`ux.coverage` は、判定が変わった時刻ごとの完了数と観測終了時点の値を残す。②は①未到達、移動なし、移動後の対象なし、または移動後に原文が残った場合は未到達。結果の `null` は秒数ゼロや成功として扱わない。全試行の到達回数と、到達した試行の中央値を併記する。①・②の比較は双方が全回到達した場合に行い、単発の差やばらつきに埋もれる差で採用しない。

`quality` は Mockingword の内部ログから行ずれによる再試行・打ち切りと、訳文からマーカー残り等を数える。`record.inventory` の未完了項目、`tools/replay-compare.mjs` の対訳も確認する。chrF は差の大きい訳を探すための値で、訳の正しさの点数ではない。同じ原文が複数ある場合、chrF は最初の1件、網羅率はDOM上の各件を数える。sakutto の内部ログに依存する品質指標は未取得とし、対訳で確認する。旧計測は両拡張の分母が異なるため、新しい指標と直接比較しない。

## 分母と訳文の判定

- 原文DOMから、段落、見出し、リスト項目、表のセル、ボタンなどのブロックを列挙する。インライン要素の文字は含める。入れ子のブロックは親に重ねて数えず、その前後にある親直下の文字も別件にする。同じ文字列が別の場所にあれば別件。
- 空白を詰め、英字またはハングルが2文字以上続き、仮名を含まない項目を対象にする。コード・数式、フォーム入力欄や編集領域、`translate=no` の原文、画像の代替テキスト、疑似要素や iframe 内は分母に入れない。本文は `main` / `article` / `[role=main]` を優先し、なければ `body` とする。ナビゲーション・補足・フッターは③からのみ除く。
- 原文の文字の矩形とCSSの表示状態で、初期画面内・表示中の画面外・非表示を区分する。閉じた `details` は `summary` 以外を別集計し、CSSで隠れたメニューも非表示に含める。メニューを開く操作はしない。非表示も、同じDOMに訳文が入ったかで判定する。
- 原文から変わり、日本語の文字を含み、元のテキストノード（英単語3語以上またはハングル4文字以上）が未変更のまま読み取り対象に残っていなければ、自動判定で完了とする。訳文の一部として書き直された人名などと、手を付けていない原文は区別する。ただし製品名だけの項目を残す正しい訳や、一部だけ日本語にした誤訳は誤判定し得る。自動値を100%にするために除外は足さず、未完了の原文・最終表示と対訳を読み、誤判定と訳し漏れを分ける。
- 保存ページ、ビューポート、端末ピクセル比、文字コード、対象項目と初期区分を記録し、同一ページ・画面条件で分母の指紋が変わったら比較を中止する。この計測では開始時のDOMを固定するため、新規挿入の自動翻訳は網羅率に混ぜず、別の機能試験で確認する。

## 実行条件

| 保存ファイル名 | ページ |
| --- | --- |
| `github-typescript-9998.mhtml` | GitHub・TypeScript Issue #9998 |
| `mdn-gpuadapter.mhtml` | MDN・GPUAdapter |
| `w3c-proposal.mhtml` | W3C・The Original Proposal of the WWW |
| `wikipedia-ko.mhtml` | 韓国語版 Wikipedia・월드 와이드 웹。メインメニューを閉じて保存する |

保存は `node tools/page-replay.mjs --save <URL> <保存先>`。実ページ・出力・外部拡張・モデルは Git 管理外に置く。各ページの基本はメインモニターで最大化したブラウザーの実ビューポートとし、画面寸法・位置・ビューポートを記録する。GitHub は別に 1200×800 CSS px でも測る。

Windows の対話デスクトップで、`BROWSER` に Chrome for Testing または Brave を指定する。試験用ブラウザーの前面化と `Alt+A` を使うため、計測中はPCを操作せず、他の重い処理も止める。各回は新しいプロファイルを使い、WebGPU・固定の0.8Bモデルが読み込まれたことを確認し、訳文キャッシュを空にする。sakutto は未改変の1.9.0と照合済みの専用GGUFを使う。拡張ごとのエンジン・モデル配布物・生成枠数は同一ではないため、実際の条件を結果に残す。保存ページとモデルはローカルから供給し、sakutto の権限は追加しない。

本計測は `default`（先送りなし・立ち上がり1本）、`a`（先送り50%）、`b`（段階送信1→4→定常）、`ab`、`sakutto` を各条件5回以上。ページ・画面の組内で開始条件を1つずつ回し、5回なら各条件が順番の1番目から5番目まで一度ずつになる。既定の Mockingword は原則8枠。`--parallel` で変える場合は混ぜずに別の結果とする。

```powershell
node tools/page-replay.mjs --ux --fixtures $fixtures --out $inventoryOut --inventory
node tools/page-replay.mjs --ux --fixtures $fixtures --out $runOut --rounds 5 --variants sakutto,default,a,b,ab --sakutto $sakutto --sakutto-model $sakuttoModel
node tools/replay-compare.mjs "$runOut/w3c-default-1.json" "$runOut/w3c-a-1.json" --out $pairsOut
```

`$fixtures` は保存した4ページのフォルダー、`$sakutto` は未改変の拡張フォルダー、`$sakuttoModel` は固定GGUF。出力のフォルダーは空にする。短い通し試験は `--pages w3c --rounds 1` を加え、条件を限定するなら `--variants` に条件名をカンマで指定する。本計測は5画面条件で125試行。`wallMs` は準備・ウォームアップも含むので、所要時間はUX指標ではなく各条件の `wallMs` と終了処理から見積もる。

## 原因を調べるときの記録

診断は Mockingword の一時コピーだけに計測点を入れる。`dispatch.occupancy` は枠取得・解放から出した同時生成本数の推移で、GPU利用率ではない。制限時間で止まった回では、終わっていない生成の枠は集計されない。`dispatch.replyToNextSend` は未送信の対象が残る受信から次の送信までの時間。次の送信がなければ `null`。`dispatch.selection` は対象の点数計算と選択1回の時間・対象数。DOM監視と診断の上乗せがあるので、絶対値は配布版の利用時間とみなさず、同じ計測条件の候補どうしで比較する。
