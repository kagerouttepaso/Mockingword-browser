# 変更履歴

版ごとの変更と、その理由・検証の事実。新しい版が上。今の状態は [現在地](00_現在地.md)、設計は各文書。

## 1.1.10の変更

- 単体GPU・外付けGPUを持つ利用者が、使う GPU を確かめ、ブラウザーに単体GPUを使わせるまでを、設定画面の「このPCの性能に合わせる」の欄でできるようにした。設計は [翻訳コア](03_翻訳コア.md)「GPU の選択と、使えない・止まったときの扱い」。
  - **使う GPU を確かめる**：設定画面を開いたときと「確かめ直す」で、モデルを読み込まずに推論エンジンを起動して GPU の報告を受け取る（wllama の `probeBackend()` をパッチで足した。数秒で、何も取得しない）。読み込み済みなら、そのモデルの報告を出す。1.1.9 は翻訳か計測でモデルを読み込むまで GPU が分からず、インストール直後や、GPU の設定を変えた後に確かめられなかった。
  - **単体GPU・外付けGPUで動かす案内**：Windows の設定（グラフィックス）と `force-high-performance-gpu` の flags を、開くボタンつきでいつも出す。拡張機能からは GPU を選べない（Windows の Chrome 系のブラウザーは `powerPreference` を採らず、ブラウザーが使う GPU はブラウザーの外で決まる）。補助プログラムは作らない（作者の判断）。
  - **測った結果の書き方を1つにした**：「このPCに合わせる」と「今の設定で測る」の結果を同じ形（`kind` が tune か speed）にし、同じ文・同じ表で出す。1.1.9 までは「今の設定で測る」だけ1行の長い文で、表が無かった。
  - 欄の並びを「使う GPU」「動作モード」「速さを測る」「細かい調整」にした。利用者向けの GPU の文は `shared/gpu.js` だけで作る。
- 検証：`npm test` 33件合格。新しいプロファイルの Brave（検証環境B、Radeon 860M）で、設定画面を開くと GPU 名（amd / rdna-3）と「ブラウザーが見せている GPU：1つ」が出ること（3通りとも同じ GPU、検算は足し算136・subgroup_size 64）、両方の「開く」ボタンが flags のタブと Windows の設定を開く確認を出すこと、2種類の測った結果が同じ書き方で出ることを確かめた。外付けGPUのノートPC（Intel の内蔵GPU＋外付けGPU）で、外付けGPUで動くことを確かめた（2026-11-25、相談者のPC）。通しの試験（`tools/e2e.mjs`、GPU の確認を追加）は未実施。

## 1.1.9の変更（試験版）

- 単体GPUと内蔵GPUの両方があるPC（Thunderbolt・USB4 の外付けGPUを含む）と、AMD・Intel の内蔵GPUで、GPU の選択と失敗の扱いを作り直した。設計は [翻訳コア](03_翻訳コア.md)「GPU の選択と、使えない・止まったときの扱い」。
  - GPU を選び、デバイスを取り、検算するのを推論エンジンの1か所にした（`tools/wllama/patches/adapter`、sakutto 0007 の移植）。拡張機能は GPU を自分で求めず、推論エンジンの報告（`offscreen/gpu.js`）を表示と調査用のログに使う。以前は拡張機能と推論エンジンが別々に GPU を求めており、画面の GPU 名が推論の GPU と同じである保証がなかった。
  - 検算が合わない・デバイスを取れないときは GPU を使わず、自動のモードでは CPU として使う。計算中に推論エンジンが止まったら、自動のモードでは CPU で読み込み直して訳し直す。以前は読み込めた後に止まると、CPU へ切り替わらず失敗し続けた。
  - 設定画面の GPU の欄に、ブラウザーが内蔵GPUを使っているときの Windows の設定の案内を出した。Windows の Chrome 系のブラウザーは `powerPreference` を採らないので、拡張機能からは GPU を選べない。
- 検証：`npm test` 33件合格（推論エンジンの報告の読み取りを追加）。同じ採用パッチ9フォルダーをこのビルド環境で作り直した WASM は、1.1.7 の同梱版とサイズが同じでコードの55バイトが違った（原因は未特定）。単体GPUと内蔵GPUの両方があるPC、Intel の内蔵GPUでの動きは未確認。

## 1.1.8の変更（試験版）

- 推論エンジンが GPU を `powerPreference: 'high-performance'` で求め、取れなければ既定で求め直すようにした試験版。拡張機能の画面も別に同じ順で GPU を求めた。外付けGPUのノートPCで high-performance でも内蔵GPUが返り、生成中に推論エンジンが止まって（`(ABORT)`）翻訳できなかった。設定画面は GPU の名前を出す処理の import が抜けていて、名前を出せなかった。1.1.9 で作り直した。

## 1.1.6の変更

## 0.14.0の変更

## 0.13.0の変更

- 最初のバッチ（見出しと第1段落）の返事を待たずに、画面内の残りの段落を空いている同時実行の枠へ送る。最初のバッチを待つ間、枠の一部しか使わず画面内の段落が待たされていた。代償として、計算の遅いGPUでは最初の訳文が遅れうる。設計は [ページの翻訳](04_ページの翻訳.md)。
- 長い段落は、まとめて1回で訳したまま、生成の途中で訳し終わった文から表示する。訳文の文の数だけ原文の文を先頭から置き換え、残りの原文は薄く残す。最後の返事で書式付きの訳文に置き換え、キャッシュには最後の返事だけを入れる。原文と訳文の文の対応は近似で、途中は1文ほどずれることがある（作者の判断：段落の訳の質を保ったまま、最初の1文から読めるようにする）。
- 横並びの一覧の項目（`li`・`dt`・`dd`）を、表示がインラインでも1件ずつ別の段落として扱う。一覧全体を1つの段落にまとめていたため、項目ごとにCSSで描く区切りの中点や入れ子の括弧が訳した後に消えていた。短い項目は送るときに今までどおりまとめて訳す。
- ページ翻訳の使い心地の計測（`tools/page-replay.mjs --ux`）を加えた。分母は計測側が翻訳前のDOMから数え、網羅は「訳文が原文から変わったか」でなく、翻訳の処理を通って確定した訳文が反映されたかで判定する。指標は「画面内に訳文が出始めるまで」「画面内で最も遅い段落の、最初の1文が読めるまで」など。定義は [ページ翻訳のUX計測](13_ページ翻訳のUX計測.md)。
- 検証：`npm test` 24件合格。保存したページで1回ずつ、最初のバッチの返事より前に画面内の別のバッチが送られること、段落の第1文と薄い原文の途中表示から訳文だけへの置き換え、一覧の区切りと括弧が残ること、パンくずの項目とリンク先が崩れないことを確かめた。性能の計測は未実施。

## 0.9.3の変更

- PDF（ブラウザーの内蔵ビューアで表示する文書）で、選んだ文章を訳せるようにした。右クリックのメニューは「選択範囲を日本語に訳す」1項目にして拡張機能の名前の下にまとめず、訳はテキスト翻訳の画面に出す。`Alt+T` はテキスト翻訳を開き、ツールバーのメニューは案内を出す。仕組みは [アーキテクチャ](02_アーキテクチャ.md)「内蔵ビューアで表示する文書」。
- Brave の自動試験で、PDFのタブを内蔵ビューアの文書と判定すること、HTMLのタブは従来どおりであること、`Alt+T` 相当の操作でテキスト翻訳が開くことを確かめた。通し試験36項目に合格（Brave）。作者の確認で、ほかの項目を `visible: false` で隠すだけでは拡張機能の名前の下にまとめられたため、取り除く形に直した。直した後、PDFでは項目がメニューの1段目に出ることを作者がBraveで確認した。PDFから複数行を選んでも訳が行ごとに途切れないことも作者が確認した。訳を出す先はテキスト翻訳のタブのままにする（作者の判断）。

## 0.9.2の変更

- 段落の中の要素（太字・斜体・リンク・コード・`<br>`・アイコンなど）を、種類を名指しせず1つの規則でマーカーにして訳文へ写し直し、原文側は段落の中身ごと隠す。GitHub の Issue で太字が消える、改行・ログの行がつながる、訳文表示で訳文の上に空行が並ぶ、を直した（作者の報告、2026-11-16）。インラインコードの空の箱の対処（`data-plamo-shell`）も同じ流れに置き換えた。
- 段落の流れを層に分けた：範囲（`page/collect.js`）、中身の読み取りと要素の分類（`page/paragraph.js`）、マーカーの文法（`shared/markup.js`）、書き込み（`page/write.js`）。設計の決まりを [設計方針](11_設計方針.md) にまとめ、`npm test` で層の依存・正本の一意性を検査する。
- 計測ツールが名前の変更（0.9.0）の後、ページのログを拾えなくなっていたのを直した（ログの頭を `shared/messages.js` の `LOG_TAG` に一本化）。
- 独自の呼び名を、開発文書・コメントでは一般の技術用語（キャッシュ、Service Worker、Offscreen Document、バッチ、マーカーなど）に、画面・プライバシーポリシー・README・ストア掲載文では一般的な名称に置き換えた。使わない言い換えの表は [設計方針](11_設計方針.md)「用語」で、`npm test` が検査する。要件に優先順位（外へ出さない＞誤訳しない＞レイアウトを崩さない＞読みやすい訳語＞速さ）と訳語の方針を明記した（[要件](01_要件.md)）。
- 通し試験36項目に合格（Brave）。性能は計測条件の安定しない時間の参考値で、前の版と同程度（`store/公開前確認.md`）。
- バッジ（MDN の「Read only」など、角の丸い小さな枠の表示）も枠の見た目ごと訳文に残す。バッジだけの行が英語のまま返っても訳し直さない（日本語の文書でも Read only のままが読みやすい、作者の判断）。文の途中の `<br>`（小文字で続く行）は空白にして文をつなぐ。理由と計測は [ページの翻訳](04_ページの翻訳.md)「マーカー」。
